# dbcomposer — чистка и пересборка библиотечных баз для Гухьятамы

PC-тулза (только Python 3.8+, без зависимостей). Исходники не трогаем — только читаем.

## Зачем

В исходных `.db` куча кривизны: строки `@ERROR`, пустые стихи, дубли, главы без стихов.
Вместо борьбы с этим в приложении — чистим один раз на компе и импортируем чистый файл
(в приложении есть импорт папкой: Настройки → «📁 Папка с .db»).

## Два режима: окно и командная строка

**Окно (проще):**
```bat
cd tools\dbcomposer
py gui.py
```
«+ Файлы .db» / «+ Папка» (сама находит `.db`, `-journal` пропускает).
Сверху вкладки: **Сборка | 📖 Лекции DOCX | 🎧 Базы Аудио | 🤖 AI-импорт** —
переключение кликом по вкладке (окна больше не открываются).
Галочка в первой колонке — книга идёт в сборку (клик или пробел).
Клик по заголовку колонки — сортировка (повторный — обратно).
Двойной клик по книге — сразу окно содержимого.
Выделил строку — внизу правишь название/автора/тип → «Применить».
Галочки чистки: `@ERROR`, пустые, дубли, пустые главы. «Обзор…» — куда сохранить,
«СОБРАТЬ» — поехали, отчёт внизу в логе.
Строки-галереи («Иллюстрации…» вместо стиха — в русской ШБ такие стоят первыми
в главах) выкидываются всегда и показываются в отчёте (`gal=N`) и в мусоре
(`галерей-строк: N`, вкладка «Галереи» в просмотрщике). Картинки при этом
не теряются — они едут через `images`/`image_nums`.

**Командная строка:**

```bat
cd tools\dbcomposer
py recompose.py inspect F:\AI\Kevala Bhakti\source\texts_rus.db
py recompose.py inspect F:\AI\Kevala Bhakti\source\texts_rus.db --type LTRS
py recompose.py build mybooks.json
py recompose.py build mybooks.json clean.db --force
py recompose.py spec        :: показать пример спеки
```

## Спека (JSON)

```json
{
  "out": "clean.db",
  "drop_error_rows": true,
  "drop_empty_verses": true,
  "dedupe": true,
  "drop_empty_chapters": false,
  "books": [
    {"file": "texts_rus.db", "book_id": 1, "title": "Бхагавад Гита"},
    {"file": "texts_rus.db", "type": "SB"},
    {"file": "songs_rus.db", "book_id": 1}
  ]
}
```

- Книга выбирается по `book_id` или по `type` (все совпавшие).
- `title`/`author`/`type` — переопределить при желании (тип лучше не менять: на него завязаны ссылки `ext:`).
- `topics_from: {file, book_id}` — СМЕРДЖИТЬ письма по темам: главы/песни берутся из книги
  тем, письма раскладываются по топикам (дубль под каждой своей темой), письма без тем —
  в раздел `untagged_title` (по умолч. "Other"). Без пересечений — обычный режим.
  В окне галочка «📨 письма по темам (LTRS+LTR)» делает то же автоматически:
  находит книгу тем (парный тип, есть главы, нет стихов), мержит и исключает её
  из сборки (иначе в приложении висят 256 пустых тем). Без книги тем — сборка
  по годам + строка-подсказка в логе. Факт merge виден в отчёте («по темам разложено: N»).
  Если в приложении темы всё равно пустые: 1) в отчёте сборки должна быть строка
  «проверка merge» с числом писем > 0 — нет её = книга собрана без merge, пересобери
  с галочкой; 2) удали в приложении СТАРЫЕ книги («Srila Prabhupada Letters»
  по годам и пустую «SP Letters by topic», долгое нажатие → 🗑) — они не заменяются
  новой смерженной книгой сами; 3) импортируй заново.
- `exclude_chapters` / `exclude_verses` — точечные исключения `[[song, number]]` / `[[song, ch, txt]]`
  (удобно ставить галочками во вкладках «Главы»/«Стихи» просмотрщика).
Окно содержимого книги (кнопка «Содержимое» или двойной клик): вкладки «Главы»
(со счётчиком стихов), «Стихи» (фильтры: все/@ERROR/дубли/пустые/без глав + поиск),
«Мусор» (расшифровка), «Картинки» (вес, габариты, привязка, описание; сортировка
кликом по «КБ»). Галочка ✕ исключает из сборки. Клик по строке картинки — предпросмотр
справа (нужен Pillow: `py -m pip install pillow`; без него — «Экспорт в папку»
и открыть её: миниатюры покажет сам проводник). Радиокнопка ○ — обложка книги.
  размер, габариты, привязка, описание; «Экспорт в папку» — посмотреть глазами).
- `drop_images: [image_id, ...]` — выкинуть мусорные картинки.
- `cover_image: image_id` — обложка из своих картинок (◉ во вкладке) или
  `cover_file: путь.jpg` — внешний JPEG. Приложение покажет её на карточке книги.
- `_id` перенумеруются заново (`texts._id = textnums._id` сохраняется — так требует приложение).
- `textrefs`: копируются исходящие от включённых типов.
- `images`/`image_nums`: только привязанные к оставленным стихам.
- `textindex*`, `meanings`, `eind`, `links`, `lettersbytopic` приложению не нужны — пропускаем.
- В конце — отчёт по каждой книге (сколько стихов, сколько мусора вычищено) + `integrity_check`.

## Аудио санскрита (MP3 -> verse_audio)

```json
{
  "out": "audio_bg.db",
  "books": [],
  "audio_pack": {
    "dir": "F:/AI/Development/gitavani-main/android/GitaVani/app/src/main/assets/audio",
    "book_type": "BG",
    "pattern": "BG{ch}.{txt}.mp3"
  }
}
```
Плейсхолдеры `{song}`, `{ch}`, `{txt}` (у тебя: `"SB{song}.{ch}.{txt}.mp3"` под
`SB1.14.29.mp3`). Выход — файл только с таблицей `verse_audio`
Сдвоенные стихи («28-29») склеиваются сами из поштучных файлов
(`SB1.14.28.mp3` + `SB1.14.29.mp3` → одна строка `28-29`): сверка идёт
по книге из той же сборки (берётся самая полная нужного типа), для чисто
аудио-сборок укажи `"verse_source": {"file": "...", "type": "SB"}`.
Нет всех частей — стих пропускается со строкой «без звука осталось» в отчёте
(вручную ничего склеивать не надо). Диапазоны из ogg не клеятся.
(book_type/song/ch_no/txt_no/content/mime): импортируется приложением как обычно
(Настройки → .db), MP3 раскладываются по ВСЕМ книгам этого типа (rus+eng).
В стихе появляется кнопка ▶ Слушать; где записи нет — TTS-оценка (кнопка «TTS»).

## Аудио: вкладка «Базы Аудио»

Всё создание аудио в одном месте, три шага по порядку:

1. **Нарезка** — отдельным приложением Audo Cut (кнопка в той же вкладке):
   режешь длинную запись на куски вручную, куски складываешь в папку.
2. **Сжатие** (`audio_recode.py`, нужен ffmpeg): MP3 64k → Opus 24k моно
   (~x3 легче, голос тот же). Структура подпапок сохраняется.
   Новые песни можно резать сразу в `.opus` — пак их ест как есть.
3. **Пак**: папка (сканируется рекурсивно) + **тип из списка** (SB/BG/…)
   + **шаблон подставляется сам** (`SB{song}.{ch}.{txt}.{ext}`; `{ext}` =
   любое из mp3/ogg/opus — смешанные папки нормально) → `audio-*.db`
   (только таблица `verse_audio`). Сдвоенные стихи склеиваются из поштучных
   MP3 по книге (поле «Книга для диапазонов»), готовые файлы диапазонов
   (`SB1.19.9-10.opus`) берутся как есть. Книги в пак не входят:
   приложение раскладывает звук по книгам этого типа при импорте
   (Настройки → .db), в стихе появляется ▶ Слушать.

## 🤖 Вкладка AI-импорт (llama-server)

Три инструмента поверх локального llama.cpp server (стандартная библиотека,
без внешних API). Сверху — сервер-бар: статус `/health` (зелёный = готов),
«Запустить сервер» (свой процесс: exe/модель/порт/контекст/аргументы
сохраняются в `ai_gui.json`), «Стоп». Уже запущенный чужой сервер на
`127.0.0.1:8080` подхватывается сам; свой гасится вместе с окном тулзы.
Свой стартует с контекстом 32768 — этого хватает на все три инструмента.

1. **1 · Разное → привязка** — файлы лекций, чьё имя не проходит парсер
   имён (уходят в «Разное»): LLM предлагает `(песнь, глава, стихи, заголовок)`,
   ревью-таблица с уверенностью и причиной → «Применить» переименовывает
   файлы (`NNN (песнь.глава.стихи) Заголовок.docx`) и перепривязывает их
   в списке лекций. Исходные файлы читаются, переименование — только по
   галочке «переименовать файлы на диске».
2. **2 · Текст → книга** — сырой txt/md → структура ПОД УПРАВЛЕНИЕМ
   пользователя: главы (Markdown-уровни / свой regex с группой `chapter` /
   автошаблоны «Глава N» / не делить) и стихи (абзац = стих / номер в строке
   / глава целиком), склейка переносов и снятие markdown. «LLM: предложить
   структуру» — подсказка границ: модель возвращает ТОЧНЫЕ строки-заголовки,
   позиции ставит код; шапка до первого заголовка → глава 0 «Введение».
   Предпросмотр дерева → «Собрать .db…» (схема источников) → «Открыть в Сборке».
   Для длинного тела смотри лимит в приложении (120k/60k/8k по типу — жёлтая
   подсказка под типом книги).
3. **3 · Метаданные** — книги из «Сборки» → LLM предлагает правки
   title/author/type (пресеты или свой запрос), каждая правка — отдельная
   строка ревью с галочкой → применяется к строкам Сборки (переименование
   при сборке). Исходные `.db` не трогаются. Крупные наборы режутся по
   60 книг за запрос.

Ответы LLM — строгий JSON (контракт в `llama_client.chat_json`: забор
```` ```json ````, сырой разбор, одна повторная попытка). Для reasoning-моделей
(GLM и др.): пустой ответ → сначала лимит ×2, затем форс `enable_thinking: off`.
Качество проверяется живьём: честный «привязка неясна» (`txts=""`,
`confidence=low`) валидация не пропускает — файл остаётся в «Разном».

## 🧩 Дельты (патчи)

Для растущих книг полный .db тянуть обидно — каталог умеет дельту: только
изменённые стихи, та же схема source-.db, приложение импортирует её тем же
импортером (upsert по координатам).

  py tools/dbcomposer/make_delta.py --old DB\Prabhupada_rus-v4.db --new DB\Prabhupada_rus-v5.db --out updates\Prabhupada_rus-delta-v5.db
  py tools/dbcomposer/make_catalog.py --src DB

В updates/versions.json у книги появляется поле
"delta": {"file": "...", "url": "...", "from": 4} — from — версия, с которой
дельта применяется; installed==from -> качается дельта, иначе полный файл.
make_catalog.py сам посчитает размер и sha256 дельты (строка «delta ... ok»,
файл не найден — «ФАЙЛ НЕ НАЙДЕН»). Стих считается изменённым, если его нет
в OLD или отличается любое общее значение колонок texts (NULL-safe).
Совпадение книг OLD<->NEW — по lower(type) (+lang, если колонка есть в обеих).

ПОРЯДОК ВЫПУСКА ПАТЧА (грамматика/опечатки): чистый .db новой версии кладётся
в DB, delta-файл — рядом (updates/), version в versions.json поднимается,
delta.from = прошлая version; затем make_catalog.py -> updates/catalog.json.

Ограничения: дельта только правит и добавляет — она НЕ удаляет стихи; релиз
с удалёнными стихами публикуй БЕЗ дельты (в versions.json delta не указывать).
Новые главы из дельты вставляются в конец. Строки одной координаты (лекции
с ~2/~3) едут целиком. deltaFrom должен совпасть с установленной версией.
Если recompose перенумеровал книги (порядок/состав спеки), make_delta сам
пишет дельту под СТАРЫЙ books._id (в отчёте — строка «ВНИМАНИЕ: ...
перенумерована»), и app-id установленной книги остаётся валидным. Для ПОЛНЫХ
файлов _id между версиями обязан быть стабилен (спеку не переставлять) —
иначе импорт откажется fail-closed.

Дельта APK (обновление приложения без полного APK):

  py tools/dbcomposer/make_apk_delta.py --old Guhyatama-45.apk --new Guhyatama-46.apk --out updates\Guhyatama-delta-45-to-46.bsdiff

В versions.json у apk добавь "delta": {"file": ..., "url": ..., "from": 45} —
from = versionCode старого APK, с которого патч применим; make_catalog.py посчитает
deltaSize/deltaSha. Клиент (Bspatch.kt) применяет патч к установленному APK
(sourceDir) и воспроизводит новый подписанный байт-в-байт; патч битый/версия
не своя — тихо качается полный APK. Нужен pip: py -m pip install bsdiff4.

## Важно для приложения

- После импорта чистого файла **удали старые книги** тех же произведений (id изменятся из-за перенумерации).
- Заметки/избранное привязаны к id стихов — после пересборки старые привязки могут осиротеть
  (покажутся как «(стих недоступен)», удалить можно крестиком).

## 🧪 Тесты (tests/)

Запуск из корня репозитория (Python 3.8+, только stdlib):

    py tools/dbcomposer/tests/test_engine.py      # движок AI-импорта: нарезка, writer, промпты
    py tools/dbcomposer/tests/test_delta.py       # make_delta: правила сравнения, перенумерация _id, битая база
    py tools/dbcomposer/tests/test_delta_e2e.py   # E2E: make_delta -> make_catalog -> импорт-мердж (семантика app)
    py tools/dbcomposer/tests/test_gui_smoke.py   # вкладка «AI-импорт» (Tk, LLM замокан)
    py tools/dbcomposer/tests/e2e_real.py         # реальные CC v2->v4: дельта + каталог с настоящих файлов
    py tools/dbcomposer/tests/test_live_e2e.py    # живой llama-server на :8080 (опционально)

`e2e_real.py` берёт файлы из `tests/real/` (или `DBCMP_DOWNLOAD=1` — качает
их с GitHub release, токен из local.properties). Каталог `tests/real/` в git
не попадает (см. `tests/.gitignore`).

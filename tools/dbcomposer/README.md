# dbcomposer — чистка и пересборка Gitabase-баз для Гухьятамы

PC-тулза (только Python 3.8+, без зависимостей). Исходники не трогаем — только читаем.

## Зачем

В исходных `.db` куча кривизны: строки `@ERROR`, пустые стихи, дубли, главы без стихов.
Вместо борьбы с этим в приложении — чистим один раз на компе и импортируем чистый файл
(в приложении есть импорт папкой: Настройки → «📁 Папка с .db»).

## Два режима: окно и командная строка

**Окно (проще):**
```bat
cd tools\dbcomposer
py gui.py
```
«+ Файлы .db» / «+ Папка» (сама находит `.db`, `-journal` пропускает).
Галочка в первой колонке — книга идёт в сборку (клик или пробел).
Клик по заголовку колонки — сортировка (повторный — обратно).
Двойной клик по книге — сразу окно содержимого.
Выделил строку — внизу правишь название/автора/тип → «Применить».
Галочки чистки: `@ERROR`, пустые, дубли, пустые главы. «Обзор…» — куда сохранить,
«СОБРАТЬ» — поехали, отчёт внизу в логе.

**Командная строка:**

```bat
cd tools\dbcomposer
py recompose.py inspect F:\AI\Kevala Bhakti\source\gitabase_texts_rus.db
py recompose.py inspect F:\AI\Kevala Bhakti\source\gitabase_texts_rus.db --type LTRS
py recompose.py build mybooks.json
py recompose.py build mybooks.json clean.db --force
py recompose.py spec        :: показать пример спеки
```

## Спека (JSON)

```json
{
  "out": "clean.db",
  "drop_error_rows": true,
  "drop_empty_verses": true,
  "dedupe": true,
  "drop_empty_chapters": false,
  "books": [
    {"file": "gitabase_texts_rus.db", "book_id": 1, "title": "Бхагавад Гита"},
    {"file": "gitabase_texts_rus.db", "type": "SB"},
    {"file": "gitabase_songs_rus.db", "book_id": 1}
  ]
}
```

- Книга выбирается по `book_id` или по `type` (все совпавшие).
- `title`/`author`/`type` — переопределить при желании (тип лучше не менять: на него завязаны ссылки `ext:`).
- `topics_from: {file, book_id}` — СМЕРДЖИТЬ письма по темам: главы/песни берутся из книги
  тем, письма раскладываются по топикам (дубль под каждой своей темой), письма без тем —
  в раздел `untagged_title` (по умолч. "Other"). Без пересечений — обычный режим.
- `exclude_chapters` / `exclude_verses` — точечные исключения `[[song, number]]` / `[[song, ch, txt]]`
  (удобно ставить галочками во вкладках «Главы»/«Стихи» просмотрщика).
Окно содержимого книги (кнопка «Содержимое» или двойной клик): вкладки «Главы»
(со счётчиком стихов), «Стихи» (фильтры: все/@ERROR/дубли/пустые/без глав + поиск),
«Мусор» (расшифровка), «Картинки» (вес, габариты, привязка, описание; сортировка
кликом по «КБ»). Галочка ✕ исключает из сборки. Клик по строке картинки — предпросмотр
справа (нужен Pillow: `py -m pip install pillow`; без него — «Экспорт в папку»
и открыть её: миниатюры покажет сам проводник). Радиокнопка ○ — обложка книги.
  размер, габариты, привязка, описание; «Экспорт в папку» — посмотреть глазами).
- `drop_images: [image_id, ...]` — выкинуть мусорные картинки.
- `cover_image: image_id` — обложка из своих картинок (◉ во вкладке) или
  `cover_file: путь.jpg` — внешний JPEG. Приложение покажет её на карточке книги.
- `_id` перенумеруются заново (`texts._id = textnums._id` сохраняется — так требует приложение).
- `textrefs`: копируются исходящие от включённых типов.
- `images`/`image_nums`: только привязанные к оставленным стихам.
- `textindex*`, `meanings`, `eind`, `links`, `lettersbytopic` приложению не нужны — пропускаем.
- В конце — отчёт по каждой книге (сколько стихов, сколько мусора вычищено) + `integrity_check`.

## Аудио санскрита (MP3 -> verse_audio)

```json
{
  "out": "audio_bg.db",
  "books": [],
  "audio_pack": {
    "dir": "F:/AI/Development/gitavani-main/android/GitaVani/app/src/main/assets/audio",
    "book_type": "BG",
    "pattern": "BG{ch}.{txt}.mp3"
  }
}
```
Плейсхолдеры `{song}`, `{ch}`, `{txt}`. Выход — файл только с таблицей `verse_audio`
(book_type/song/ch_no/txt_no/content/mime): импортируется приложением как обычно
(Настройки → .db), MP3 раскладываются по ВСЕМ книгам этого типа (rus+eng).
В стихе появляется кнопка ▶ Слушать; где записи нет — TTS-оценка (кнопка «TTS»).

## Напевная озвучка Vagdhenu (ШБ и др., нужен ПК с NVIDIA GPU)

Движок `prathoshap/vagdhenu` (Apache-2.0) поёт шлоки с соблюдением метра —
то, что обычный TTS не умеет. Телефон такое не тянет, поэтому рендерим на ПК
(RTX 4090 хватает за глаза), в приложение едет готовый Opus-пак.

1. Развернуть движок (Python 3.10, CUDA 12.1):
   `bash scripts/setup.sh` в клоне vagdhenu — положит веса в `models/`.
2. Выгрузить шард из исходной gitabase-базы (деванагари, пады, авто-метр):
   ```
   py vagdhenu_shard.py shard --src gitabase_sb.db --book-type SB \
       --out shard_sb.json --manifest manifest_sb.json --outdir C:/vag/wav
   ```
   Проверь `manifest_sb.json`: поле `meter_source=guess` — спорные метры,
   правки — файлом `--meter-map fixes.json` (`{"SB-1-2-3": "vasantatilaka"}`).
3. Рендер: `python src/render.py --shard shard_sb.json --results res.json --outdir C:/vag/wav`
   (модель грузится один раз, дальше идёт по клипам; падения видны в `res.json`).
4. Сборка ogg под пак:
   ```
   py vagdhenu_shard.py collect --manifest manifest_sb.json --results res.json \
       --wavdir C:/vag/wav --outdir sb_ogg --pattern "SB{song}.{ch}.{txt}.ogg" --bitrate 24k
   ```
   Opus 24k моно ≈ 60–90 КБ/стих, весь ШБ ≈ 1 ГБ — пакуй по песням отдельными прогонами.
5. `audio_pack`: `{"dir": "sb_ogg", "book_type": "SB", "pattern": "SB{song}.{ch}.{txt}.ogg"}`
   → `audio_sb.db` → импорт в приложении. OGG/Opus поддерживается плеером
   (файлы `..._..._....ogg` рядом с mp3), mime едет в `verse_audio.mime`.

## Свой темп/манера: кастомный банк эталонов (поле «Банк эталонов» в окне)
Параметры темпа (`speed`) длительность почти не меняют: холст генерации фиксирован
через `sps`, лишнее срезает гейт. Единственный архитектурно-чистый рычаг темпа —
**эталонный клип**: движок копирует темп/голос/мелодику с референса метра.
Чтобы пелось медленнее/иначе:
1. Скопируй папку `src/reference_bank` движка, запиши СВОИ эталоны (чистый микрофон,
   без реверберации): минимум `anushtubh.wav`, лучше все нужные метры.
2. Для каждого clip'а `ref_text` обязан ДОСЛОВНО совпадать с произнесённым
   (half-reference rule, граница по слову/данде), иначе поедет выравнивание.
3. Свой `bank.json` того же формата (`wav`, `ref_text`, `sec_per_syll` —
   секунд на слог: больше = медленнее, стартовать с `sps_штатный × 1.15`).
4. Укажи свой `bank.json` в поле окна — рендер возьмёт его (`--bank`).
Метр из шарда должен совпасть с ключом банка, иначе будет fallback с предупреждением.

## Важно для приложения

- После импорта чистого файла **удали старые книги** тех же произведений (id изменятся из-за перенумерации).
- Заметки/избранное привязаны к id стихов — после пересборки старые привязки могут осиротеть
  (покажутся как «(стих недоступен)», удалить можно крестиком).

# Релизы и обновления — уроки

## task: релиз v1.3.8 + починка каналов обновления (2026-10-25)
- task_id: release-1.3.8-update-channels
- harness_adopted: воркер по одному ТЗ + личная проверка ключевых утверждений (grep/read/GitHub API), правки малыми коммитами
- why_chosen: аудиты воркера дважды содержали ложные «критичные» находки; проверка чтением кода и API дешевле, чем откат ложных правок
- transferable_lesson:
  1. Клиент читает каталог из ветки `main` (default branch), а не из имени локальной ветки. Релиз, запушенный в `master`, для клиентов невидим: `main` отставал на 3 коммита, приложение писало «нет обновлений». Проверка после релиза — raw/API каталога, а не только `git push`.
  2. `raw.githubusercontent.com` кэширует ~5-15 мин, query-string (`?cb=`) кэш НЕ обходит. Надёжный канал — каталог ассетом техрелиза с фиксированным тегом `catalog` (prerelease): `releases/download/catalog/catalog.json`. URL стабилен, ассеты immutable.
  3. Fail-closed приложение не качает книги без `sha256`; `make_catalog.py` при отсутствии исходных `.db` обнулял size/sha. Лечение: сохранять значения из предыдущего каталога (сверка key+url) и восстанавливать реальные суммы из истории git — проверять на одном ассете потоковым sha256.
  4. При ошибках сети приложение должно показывать класс+текст исключения (`asset:/raw:/api:`) и иметь запасной источник; общий текст «Нет связи с сервером» скрывал и TLS, и DNS, и HTTP-код.

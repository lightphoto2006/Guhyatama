# Сессия 2026-10-25 — журнал решений

## Android-приложение
- minSdk 26→24 (Android 7), adaptive-иконки в mipmap-anydpi-v26 + растровые fallback (v1.3.8, fa06993).
- Канал обновлений: каталог публикуется ассетом техрелиза `catalog` (prerelease), приложение читает releases/download/catalog/catalog.json; raw и API contents — резерв. Причина: raw.githubusercontent кэширует 5-15 мин и не обходит кэш по query-string.
- Сетевые ошибки: показывается класс+текст исключения, причина по каждому источнику (asset/raw/api).
- Встроен ISRG Root X1 + networkSecurityConfig (system+user CA): Android 7.0 не доверяет Let's Encrypt (release-assets.githubusercontent.com).
- Свой потоковый загрузчик (fetchStream) вместо DownloadManager (на EMUI сервис отсутствует); DownloadManager — только фолбэк.
- Проза: PROSE_TYPES = GC/CHB; неизвестные типы читаются как стихи. Лимит тела для новых типов 8k→120k.
- Очистка дублей: при импорте полного файла удаляются книги, ставившиеся этим ключом, но пропавшие из нового файла.
- Установка APK: canRequestPackageInstalls вызывается только через рефлексию на API 26+; любые ошибки установки ловятся (Throwable) и показываются текстом (падало на Android 7 NoSuchMethodError).
- История версий: 1.3.8 (vc56) → 1.3.9 (57) → 1.3.10 (58) → 1.3.11 (59) → 1.3.12 (60) → 1.3.13 (61) → 1.3.14 (62) → 1.3.15 (63).

## Публикация книг
- dbcomposer: «Δ Дельта БД» → блок «Публикация книги» — одной кнопкой: make_delta (--force), GitHub release db-vN, upload full+delta, versions.json, make_catalog, patch size/sha, git push, publish_catalog.
- Можно публиковать НОВЫЙ ключ (название+язык) прямо из вкладки.
- Дельта не публикуется, если патч ≥98% полного файла; для первой версии ключа — не нужна.
- Дельта НЕ передаёт обложки — при смене обложки публиковать полный файл.
- Каталог: make_catalog сохраняет size/sha256 из предыдущего каталога, если исходных .db нет (регресс с обнулением сумм лечился восстановлением из истории каталога).
- Сборник Acharyi_rus: v8 (BG-SS+BS+GC), v9 — стабильные _id (GC=1, BG-SS=2, BS=3); смена _id даёт дубли в приложении.
- Ветка одна — main (master удалён); клиент читает main.

## dbcomposer (инструмент)
- Вкладка «Релиз» и «Δ Дельта/Каталог»: консольные окна скрыты (CREATE_NO_WINDOW), токен GitHub кэшируется (вход на вкладку 0.04 с вместо ~2 с).
- Общий uicommon: лог, Ctrl+C/V/X/A по физическому коду клавиши (русская раскладка), контекстное меню логов.
- Окно помнит геометрию и активную вкладку.
- Сборка: кнопка СТОП (cancel в recompose.build), при отмене «ОТМЕНЕНО», tmp удаляется.
- build() разбит на _build_validate/_build_schema/_build_books/_build_finalize; эталонная сборка совпала по sha256 (2616f3da…).
- Дельта: запоминаются OLD/NEW/OUT; в ошибке указана вкладка; проверка файлов до запуска.
- AI-импорт: тип книги вводится вручную (2–8 символов A–Z/0–9); названия глав из строки заголовка или следующей строки; главы словами («Глава первая»); отсечение блока СОДЕРЖАНИЕ; прогресс LLM по чанкам; автодетект структуры (🔎 Автоопределить) по строкам + нормализация; regex из выделенной строки.
- Обложка: задаётся при импорте (поле «Обложка:» → writes to source .db) и переносится в сборку автоматически; также кнопка в «Сборке» и в окне книги (JPEG/PNG).

## Решения и почему
- Каталог в ассете релиза: immutable-URL, нет устаревшего кэша.
- Рефлексия для API 26: прямой вызов роняет приложение на Android 7 (NoSuchMethodError).
- Стабильные _id при сборке: id книги = часть app-id (gb-<type>-<n>-<lang>).
- Не публиковать дельту ≥98%: экономия трафика.
